## 1. Обзор

Система позволяет пользователям регистрироваться, подтверждать email и авторизоваться в личном кабинете через HTTP(S) API.

## 2. Проблема

Пользователи должны иметь безопасный и удобный доступ к личному кабинету с возможностью:
- Создать аккаунт за пару кликов
- Получить подтверждение через email
- Войти в систему и получить доступ к персональным данным
- Безопасно управлять сессиями

## 3. Решение

### 3.1 Архитектура аутентификации

- **Тип:** JWT токены (Access + Refresh)
- **Access Token:** 30 минут (в памяти браузера)
- **Refresh Token:** 7 дней (HTTP-only cookie)
- **Структура endpoints:** `/v1/auth/*`

### 3.2 Процесс регистрации

1. Пользователь отправляет `POST /v1/auth/register` с email, паролем и именем
2. Система создает пользователя в состоянии "не подтвержден"
3. Система генерирует одноразовый token и отправляет email со ссылкой
4. Пользователь переходит по ссылке `https://mystore.com/verify?token={token}`
5. Система подтверждает email и выдает JWT токены

### 3.3 Процесс авторизации

1. Пользователь отправляет `POST /v1/auth/login` с email и паролем
2. Система проверяет credentials и подтвержденный email
3. Система выдает Access + Refresh токены

### 3.4 Управление сессиями

- **Refresh Token** хранится в HTTP-only cookie
- При каждом обновлении токен инвалидируется (одноразовость)
- Access token хранится в памяти браузера

## 4. Требования к пользовательскому опыту

### 4.1 Минимальные поля при регистрации
- **Обязательные:** email, password, name
- **Опциональные:** телефон, дата рождения (в будущем)

### 4.2 Требования к паролю
- Минимальная длина: 8 символов
- Сложность: не проверяется жестко (но рекомендуется)

### 4.3 Email-подтверждение
- Формат: URL с token в query параметре
- Срок действия: 24 часа
- Одноразовость: token удаляется после использования

## 5. Безопасность

### 5.1 Хэширование паролей
- **Алгоритм:** argon2id
- **Параметры:**
  - Memory: 64 MB
  - Iterations: 3
  - Parallelism: 4
  - Type: Argon2id

### 5.2 Rate Limiting
| Endpoint | Лимит | Перезарядка |
|----------|-------|-------------|
| POST /v1/auth/register | 3/ч | 1 ч |
| POST /v1/auth/login | 5/мин | 5 мин |
| POST /v1/auth/resend-verification | 2/ч | 1 ч |
| POST /v1/auth/forgot-password | 3/ч | 1 ч |

### 5.3 Блокировка при неудачных попытках
- 5 неудачных попыток → блокировка на 15 минут
- 10 неудачных попыток → блокировка на 24 часа

### 5.4 Логирование
- Все события аутентификации должны логироваться
- IP-адрес, email, результат (успех/неудача), timestamp

## 6. Валидация и ошибки

### 6.1 Коды ошибок

Канонический список кодов — `04-api-reference.md`, раздел 4.0.

| Код | Описание |
|-----|----------|
| `VALIDATION_ERROR` | Ошибка валидации данных (коды полей — в `details.fields`) |
| `EMAIL_ALREADY_REGISTERED` | Email уже зарегистрирован |
| `EMAIL_NOT_CONFIRMED` | Email не подтверждён |
| `EMAIL_ALREADY_CONFIRMED` | Email уже подтверждён |
| `CONFIRMATION_TOKEN_INVALID` | Неверный или истёкший токен подтверждения |
| `INVALID_CREDENTIALS` | Неверный email или пароль |
| `ACCESS_TOKEN_INVALID` | Неверный или истёкший токен доступа |
| `REFRESH_TOKEN_INVALID` | Неверный или истёкший токен обновления |
| `INVALID_TOKEN` | Неверный токен (сброс пароля, отписка) |
| `EXPIRED_TOKEN` | Токен сброса пароля истёк |
| `TOKEN_REVOKED` | Токен отозван (чёрный список) |
| `TOKEN_NOT_FOUND` | Токен не найден |
| `USER_NOT_FOUND` | Пользователь не найден |
| `WEAK_PASSWORD` | Пароль не соответствует требованиям |
| `RATE_LIMITED` | Превышен лимит запросов |

### 6.2 HTTP статусы
- `201 Created` — ресурс создан
- `400 Bad Request` — ошибка валидации + JSON errors
- `401 Unauthorized` — неверный/истекший токен
- `403 Forbidden` — токен заблокирован
- `409 Conflict` — дублирование, уже подтвержден
- `429 Too Many Requests` — rate limit

### 6.3 Формат ошибок

Все ошибки используют единый конверт (см. `04-api-reference.md` §4.0 и `references/openapi.yaml` → `ErrorResponse`):

```json
{
  "error": {
    "code": "EMAIL_ALREADY_REGISTERED",
    "message": "Пользователь с этим email уже существует",
    "details": {}
  }
}
```

- `code` — стабильный машинный код (см. §6.1);
- `message` — человекочитаемое описание на русском;
- `details` — опциональный объект со структурированными данными.

Ошибки валидации (`400 VALIDATION_ERROR`) содержат массив `details.fields`:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Ошибка валидации данных",
    "details": {
      "fields": [
        { "field": "email", "code": "INVALID_FORMAT" },
        { "field": "password", "code": "TOO_SHORT" }
      ]
    }
  }
}
```

Для `429 RATE_LIMITED` в `details` передаётся `retry_after` (в секундах).

## 7. Успешные критерии

- [ ] Пользователь может зарегистрироваться за 3 шага
- [ ] Email подтверждается в течение 1 минуты
- [ ] Авторизация занимает менее 1 секунды
- [ ] Все пароли хэшируются argon2id
- [ ] Rate limiting работает корректно
- [ ] Refresh tokens инвалидируются после использования
- [ ] Логирование всех auth событий включено

## 8. Исключения и edge cases

| Сценарий | Поведение |
|----------|----------|
| Регистрация с уже существующим email | 409 + `EMAIL_ALREADY_REGISTERED` |
| Попытка входа с неподтвержденным email | 403 + `EMAIL_NOT_CONFIRMED` |
| Использование уже использованного token | 409 + `EMAIL_ALREADY_CONFIRMED` |
| Истекший token подтверждения | 400 + `CONFIRMATION_TOKEN_INVALID` |
| Неверный refresh token | 401 + `REFRESH_TOKEN_INVALID` |
